Realmbound Encounter Editor

This guide explains how to read story/encounters.json and add a new battle that automatically appears in both the Python and HTML5 versions of Realmbound.

The rule that prevents your encounter from disappearing

Every encounter you create must contain "user_added": true. The encounter generator rebuilds the file from the game. It preserves custom entries only when they are marked as user-added. Leaving this out can cause your custom encounter to be removed the next time the generator runs.
JSON does not allow comments. Do not put // explanation or # explanation inside the JSON file. The examples in this guide are valid JSON and can be copied directly.

How the file is organized

You only need to understand three areas to add an encounter.

1. data_encounters

The complete definition of each JSON-controlled encounter: enemy, intro, running result, and rewards.

2. scenes

Each story scene has an after_scene list. Put your encounter ID there to make it run.

3. monsters

A reference list of enemy stats. At present, it is generated for reading and is not the combat engine's editable source.

What the major sections mean

SectionPurposeShould you edit it?
scene_orderThe order of the main story scenes.Usually no.
scenesReadable scene summaries and encounter lists.Edit only the scene's after_scene list for normal additions.
scenes.*.encountersA generated list of encounters already controlled by custom Python/JavaScript scene logic.No. It is mainly a map of the existing story.
data_encountersFull definitions for data-controlled encounters.Yes. Add your custom encounter here.
monstersA readable copy of monster stats.Not currently. Editing it does not yet change combat stats.
sequencesInformation about special sequences such as the Hundred-Day Road.Not currently.

Add a new battle

This example adds an Angry Bridge Goblin after the Village scene.

Choose an existing enemy

Use an enemy name already listed under monsters. This example uses goblin.

Create a unique ID

Use lowercase letters and underscores. Example: angry_bridge_goblin.

Add the full object to data_encounters

Put a comma after the previous object, then paste the encounter below.

Inside the data_encounters object
"angry_bridge_goblin": {
  "id": "angry_bridge_goblin",
  "name": "Angry Bridge Goblin",
  "scene": "village",
  "user_added": true,
  "type": "battle",
  "enemy": "goblin",
  "intro": [
    "A goblin jumps from beneath the bridge and demands a crossing fee."
  ],
  "choice": "fight_or_run",
  "run": {
    "text": "The goblin catches you before you reach the road.",
    "game_over": true
  },
  "victory": {
    "rewards": [
      {
        "money": {
          "min": 5,
          "max": 12
        }
      }
    ],
    "offer_potions": true
  }
}

Add its ID to the scene

Find scenes → village → after_scene and add the exact same ID.

Village scene placement
"village": {
  "title": "Village",
  "summary": "Save the village, receive a potion, and visit Gnome Depot.",
  "encounters": [
    ...existing generated entries stay here...
  ],
  "after_scene": [
    "angry_bridge_goblin"
  ]
}
That is enough to connect the battle. When the Village scene finishes, the Python and HTML5 versions read the ID from after_scene, load its object from data_encounters, and run it.

Shops, churches, choices, and completely custom sequences

A custom encounter can now be more than a battle. Top-level encounters and nested sequence steps use the same types, so you can combine dialogue, choices, churches, shops, rewards, and battles in any order.

Optional shop

A named advanced shop
"last_chance_caravan": {
  "id": "last_chance_caravan",
  "name": "Last-Chance Caravan",
  "scene": "well",
  "user_added": true,
  "type": "shop",
  "intro": ["A supply caravan waits beside the road."],
  "prompt": "Stop at the caravan? (yes/no): ",
  "optional": true,
  "advanced": true,
  "legendary": false,
  "enter_text": ["The merchant opens the supply crates."],
  "decline_text": ["You continue down the road."],
  "leave_text": "You leave the caravan."
}

advanced and legendary select which existing store inventory tier is available. The shop keeps normal stock and purchase behavior.

Church that asks before restoring the player

Optional full restoration
"mossy_lantern_church": {
  "id": "mossy_lantern_church",
  "name": "Church of the Mossy Lantern",
  "scene": "forest",
  "user_added": true,
  "type": "church",
  "intro": ["A tiny stone church glows between the trees."],
  "prompt": "Go inside? (yes/no): ",
  "optional": true,
  "enter_text": ["The caretaker offers you a quiet pew."],
  "decline_text": ["You stay on the forest road."],
  "restore": {
    "health": "full",
    "mana": "full"
  },
  "rest_text": "You leave fully restored."
}

Instead of "full", use a number such as 25 to restore only that amount. Omit either health or mana to leave that stat unchanged.

Completely custom sequence with a nested choice

Dialogue → choice → church or shop
"crossroads_stop": {
  "id": "crossroads_stop",
  "name": "Crossroads Stop",
  "scene": "mountain_pass",
  "user_added": true,
  "type": "sequence",
  "steps": [
    {
      "type": "text",
      "text": ["Two lanterns glow beside the road."]
    },
    {
      "type": "choice",
      "prompt": "Visit the chapel instead of the trader? (yes/no): ",
      "yes": [
        {
          "type": "church",
          "name": "Travelers' Chapel",
          "optional": false,
          "restore": { "health": "full", "mana": 30 },
          "rest_text": "You rest beneath the lanterns."
        }
      ],
      "no": [
        {
          "type": "shop",
          "name": "Mountain Trader",
          "optional": false,
          "advanced": true
        }
      ]
    },
    {
      "type": "reward",
      "rewards": [{ "item": "Small Health Potion" }],
      "text": ["A traveler gives you a spare potion before you leave."]
    }
  ]
}
Supported nested step types text, choice, battle, shop, church, rest, reward, and another sequence. A choice uses yes and no arrays containing more steps.

Encounter field reference

FieldRequired?Meaning
idRequiredThe encounter's unique identifier. It must match its key and the ID placed in after_scene.
nameRecommendedA readable name for humans. The current runtime does not print it automatically.
sceneRecommendedDocuments which scene the encounter belongs to. Actual placement is controlled by after_scene.
user_addedRequiredMust be true so the generator preserves the custom encounter.
typeRequiredUse "battle", "shop", "church", "sequence", "choice", "text", or "reward".
enemyRequiredThe exact lowercase name of an enemy that already exists in the game's combat data.
introOptionalAn array of text lines shown before the battle.
choiceOptionalUse "fight_or_run" to ask the player. Leave it out to start the battle immediately.
runOptionalControls the result when the player runs. It can show text and optionally cause game over.
victory.rewardsOptionalA list of item and money rewards granted after victory.
victory.offer_potionsOptionalWhen true, opens the normal potion-use prompt after the battle.
victory.text now works in both ports. Use it for dialogue or narration that should appear only after the player wins.

Reward examples

Fixed money

Exactly 20 Whoop Nickels
"rewards": [
  { "money": 20 }
]

Random money

Between 10 and 25
"rewards": [
  {
    "money": {
      "min": 10,
      "max": 25
    }
  }
]

Item reward

Adds an inventory item
"rewards": [
  { "item": "Moon Cheese" }
]

Money and an item

Multiple rewards
"rewards": [
  { "money": 15 },
  { "item": "Small Health Potion" }
]

Use "rewards": [] when the encounter should give nothing.

Where an encounter runs

Custom JSON encounters currently run from a scene's after_scene list. They run after that scene's existing coded story finishes and before the game advances to the next normal checkpoint.

Multiple encounters run from top to bottom

Three added battles in order
"after_scene": [
  "angry_bridge_goblin",
  "bridge_troll",
  "lost_skeleton"
]

The goblin runs first, then the troll, then the skeleton.

Do not add the ID to encounters

The encounters list describes battles and events already found inside the original scene code. The generator rebuilds that list. Put custom IDs in after_scene instead.

What this system can and cannot do yet

Works now

  • Add battles, shops, churches, rest stops, rewards, and text.
  • Ask yes/no questions and run different nested steps for each answer.
  • Combine steps into completely custom sequences.
  • Name shops and select normal, advanced, or legendary stock.
  • Restore full or partial health and mana.
  • Give fixed money, random money, items, health, or mana.
  • Run the same encounter in Python and HTML5.

Not data-driven yet

  • Creating a completely new monster only in JSON.
  • Changing monster stats by editing the generated monsters section.
  • Inserting an encounter halfway through an existing coded scene.
  • Automatically syncing JSON additions to the separate C++ or legacy branches.
An enemy must already exist in both connected ports. The Python and HTML5 combat engines still own brand-new monster definitions. Pick a name already listed under monsters. Adding a brand-new name only to the JSON will cause an unknown-monster error.

Validate and test your edit

1. Check the JSON syntax

Run from the repository root
python3 -m json.tool story/encounters.json > /dev/null

No output means the JSON syntax is valid. An error gives the approximate line and column that need fixing.

2. Test the Python version

Start Realmbound
python3 main.py

3. Test the HTML5 version

Start a local web server
python3 -m http.server 4173

Open http://127.0.0.1:4173/. Do not open index.html directly as a local file, because the browser needs to fetch story/encounters.json.

HTML5 deployment requirement The hosted game now needs story/encounters.json alongside index.html and the web/ folder. Upload the story/ folder when deploying the browser port.

Common mistakes

ProblemWhat happensFix
Missing "user_added": trueThe generator may erase the custom entry.Add the field to every custom encounter.
ID does not matchThe game reports an unknown encounter.Make the object key, id, and after_scene value identical.
Enemy name is misspelledCombat cannot find the monster.Copy the exact lowercase name from monsters.
Missing commaThe entire JSON file fails to load.Put commas between neighboring properties and objects, but not after the final one.
Added ID to encountersThe addition may be overwritten and will not be executed as a custom encounter.Add it to after_scene.
Edited generated monster statsThe displayed JSON changes, but actual combat may not.Monster stats are not JSON-controlled yet.
Used JSON commentsThe JSON parser fails.Remove all //, /* */, and # comments.
Forgot to upload the story folderThe browser game fails while loading encounter data.Deploy story/encounters.json with the HTML5 port.

Final checklist

  • The custom object is inside data_encounters.
  • The object has "user_added": true.
  • The object key and its id are identical.
  • The enemy name already exists.
  • The ID is in exactly one intended scene's after_scene list.
  • python3 -m json.tool story/encounters.json succeeds.
  • Every branch of the encounter is tested in both Python and HTML5.
